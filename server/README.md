# Chatbot server

Flask API with a local RAG pipeline: knowledge files and web pages are chunked,
embedded with a multilingual MiniLM model, and searched by hybrid (dense + BM25)
retrieval. Answers are generated by Gemma through Google's Gemini API using only
the retrieved context, streamed token by token, and the UI renders the sources
that were cited.

## Quick start

```powershell
cd server
python -m venv .venv
.\.venv\Scripts\activate
pip install -r requirements.txt

copy .env.example .env    # then set GEMINI_API_KEY

python ingest.py         # fetch URLs + build the index
python app.py            # http://127.0.0.1:5001
```

The Vite dev server proxies `/api` to port 5001, so run the client separately.
Manage knowledge from the client's **Library** page (upload, delete, reindex)
or with `python ingest.py`. While indexing, the page shows a package-manager style log — files parsed,
per-document chunk counts, embedding batches, save and completion — plus a
progress bar and elapsed time, fed by `GET /api/index/progress`. The log stays
visible after the run finishes (until dismissed) and the panel offers
**Upload another**, **Add another**, **Retry**, and **Dismiss** actions. Each
web-page row also has **Fetch / Re-fetch** (re-download and re-index) and delete.

## Deploy on Render (free plan)

Build: `pip install -r requirements.txt && python ingest.py`
Start: `gunicorn -w 1 --threads 4 -t 120 -b 0.0.0.0:$PORT app:app`

Set Render's root directory to `server`. Keep `ADMIN_ENABLED=0` so the
deployed API stays read-only, and set `ALLOWED_ORIGIN` to the deployed
client's origin. Render provides `PORT`.

## API

| Route | Purpose |
| --- | --- |
| `GET /api/hello` | Health check used by the home page. |
| `GET /api/health` | Index stats: chunks, documents, model, dimensions, build time. |
| `POST /api/chat` | `{ "message", "history" }` → `{ "reply", "sources" }` (one JSON response). |
| `POST /api/chat/stream` | Same body, SSE response: `sources`, `token`, `done`/`error` events. |
| `GET /api/documents` | Knowledge files, configured URLs, index stats. |
| `GET /api/index/progress` | Live indexing state: `stage`, `detail`, `done`/`total`, `percent`, `elapsed`. |
| `POST /api/documents` | Multipart `file` (`.md`, `.txt`, `.pdf`, ≤ 2 MB) → rebuilds the index. |
| `DELETE /api/documents/<name>` | Deletes a knowledge file → rebuilds the index. |
| `POST /api/documents/urls` | `{ "url": str }` → fetches the page, saves it to `urls.txt`, rebuilds the index. |
| `POST /api/documents/urls/refresh` | `{ "url": str }` → re-fetches an existing URL and rebuilds the index. |
| `DELETE /api/documents/urls` | `{ "url": str }` → removes the URL and its cache, rebuilds the index. |

Chat requests return `400` for an empty or over-long message, `413` for an
oversized upload, and `502` when the LLM call fails, all with a JSON `error`.

## Pipeline

1. **Sources** — every `knowledge/*.md|*.txt|*.pdf` file (except `urls.txt`),
   plus pages cached from `knowledge/urls.txt`. Web pages can be added from the
   client's Library page (or by editing `urls.txt` directly) and are fetched
   when added; unreachable URLs stay in the list and are retried on the next
   `python ingest.py`. A leading bare URL in a markdown file becomes the source
   link and is removed from the chunked text.
2. **Sanitising** (`rag/safety.py`) — HTML comments and obvious prompt-injection
   lines are stripped before indexing; the system prompt also delimits context
   with `<context>` tags and tells the model it is data, not instructions.
3. **Chunking** (`rag/chunking.py`) — paragraph and sentence boundaries, bullet
   lines preserved, markdown headings prepended as a `Section > Subsection`
   breadcrumb. Chunks overlap so facts split across a boundary stay retrievable.
4. **Embedding** (`rag/embedder.py`) — `fastembed` ONNX model
   `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`, cached in
   `.cache/models` (not `%TEMP%`, which gets wiped).
5. **Index** (`rag/index.py`) — normalised vectors persisted to `.index/`
   (`index.json` + `vectors.npy`) and reloaded on start. A fingerprint of source
   file stats, model name and chunk settings decides whether the cache is valid,
   so editing a document triggers a rebuild on the next request. Set
   `INDEX_VERSION` in `config.py` when chunking or index format changes.
   Startup warms the index and embedding model in a background thread.
6. **Retrieval** (`rag/search.py`) — dense cosine and BM25 scores are fused with
   reciprocal rank fusion, near-duplicate chunks are dropped, candidates above
   the score floor are reranked by the generation model, and at most
   `RAG_MAX_PER_SOURCE` chunks per document survive. Weak matches are dropped;
   if nothing clears the threshold the service answers with a fixed "not in my
   documents" message without calling the generator.
7. **Generation** (`chat/service.py`) — context numbered per document so `[n]`
   citations match the numbered source list, history trimming to
   `HISTORY_MESSAGES`, and a short-follow-up rule that also searches the
   previous question when the current message has no topic of its own.
8. **Conversation flow** (`chat/intent.py`) — greetings, thanks, "what can you
   do", vague requests ("give me info"), and short reactions ("what?", "huh?")
   get a short conversational answer that lists the covered topics and asks for
   clarification, instead of the "not in my documents" refusal. Reactions are
   not treated as a new question. Questions with no retrieved context also go
   through this friendly mode, which may only offer the topic list and must not
   answer factual questions from outside knowledge. When context exists but
   only answers part of a question, the model answers what it can and names the
   gap. Sources are citations: an answer that cites nothing shows no source
   list, so chatty replies never inherit irrelevant retrieved matches. If a
   retrieved context still produces the canonical refusal, the reply is
   regenerated in conversational mode with the topic menu (streams peek at the
   first sentence and switch before showing a bare refusal).

Rebuild explicitly with `python ingest.py` (fetches URLs) or
`python ingest.py --local-only` (reuses the URL cache). Delete `.index/` to
force a cold rebuild.

Uploads through the API are capped by `MAX_UPLOAD_BYTES` (10 MB by default).
Local ingestion has **no size cap**: copy files into `knowledge/` and run
`python ingest.py`; indexing time then scales with text volume (~80 chunks/s
embedding, ~10k chars/s PDF extraction).

## Code map

The RAG code is split by responsibility; `rag/store.py` is a thin facade that
re-exports the public functions (`search`, `stats`, `rebuild`, `warm`, progress
helpers), so imports elsewhere stay short.

| Module | Responsibility |
| --- | --- |
| `rag/store.py` | Facade: re-exports the pipeline (`from rag import search, stats, rebuild, warm`). |
| `rag/progress.py` | Indexing stage + rolling log used by `GET /api/index/progress` and the Library panel. |
| `rag/sources.py` | Read `knowledge/` files and cached web pages into `{id, title, url, text}`; PDF text cache; source fingerprints. |
| `rag/index.py` | Chunk, embed (reusing unchanged vectors), fingerprint, save/load `.index/`, rebuild, warmup. |
| `rag/search.py` | Hybrid retrieval: dense + BM25 → RRF → dedupe → rerank → per-source cap. |
| `rag/chunking.py` | Paragraph/sentence-aware chunking with heading breadcrumbs. |
| `rag/embedder.py` | `fastembed` model wrapper (model cached under `.cache/models`). |
| `rag/keyword.py` | Tokeniser, BM25 implementation, reciprocal rank fusion. |
| `rag/rerank.py` | Optional LLM rerank of fused candidates. |
| `rag/loaders.py` | File/URL text extraction (trafilatura + pypdf) and title helpers. |
| `rag/safety.py` | Strip HTML comments/prompt-injection lines before indexing. |
| `rag/urls.py` | Manage `knowledge/urls.txt` and the URL text cache (add/remove/refresh). |

## Configuration

Most settings come from `.env` (see `config.py` for defaults):

| Variable | Default | Meaning |
| --- | --- | --- |
| `LLM_PROVIDER` | `gemini` | Only `gemini` (Gemma) is supported. |
| `GEMINI_API_KEY` | — | Required for the `gemini` provider. |
| `GEMINI_MODEL` | `gemma-4-26b-a4b-it` | Gemini native model id for answers. |
| `FIELD_NAME`, `PERSONA`, `AUDIENCE`, `TONE` | — | Prompt shaping. |
| `EXTRA_RULES` | — | Extra system-prompt rules. |
| `TEMPERATURE` | `0.2` | Sampling temperature. |
| `HISTORY_MESSAGES` | `6` | Prior turns sent to the model. |
| `PORT` | `5001` | Flask port. |
| `ADMIN_ENABLED` | `0` | `0` hides every upload/URL/delete/rebuild route (404). |
| `ALLOWED_ORIGIN` | — | Only origin allowed to call the API cross-origin; empty = same-origin only. |
| `EMBED_MODEL` | multilingual MiniLM | `fastembed` model name. |
| `RAG_TOP_K` | `5` | Chunks kept per question. |
| `RAG_MIN_SCORE` | `0.30` | Minimum cosine similarity. |
| `RAG_CANDIDATES` | `20` | Candidates passed to the reranker. |
| `RAG_MAX_PER_SOURCE` | `3` | Max chunks from one document. |
| `RAG_BM25_MIN` | `1.5` | BM25 score that can admit a low-dense chunk. |
| `RAG_RERANK` | `1` | LLM rerank on/off. |
| `RAG_RERANK_MODEL` | `openai/gpt-oss-20b` | Reranker model (fast). |
| `RAG_RERANK_EFFORT` | `low` | Reasoning effort for the reranker. |
| `RAG_CHUNK_CHARS` / `RAG_CHUNK_OVERLAP` | `800` / `120` | Chunk size and overlap. |
| `MAX_MESSAGE_CHARS` | `500` | Rejects longer questions. |
| `MAX_UPLOAD_BYTES` | `10485760` | Upload size limit (10 MB). Files copied directly into `knowledge/` are not limited. |
| `WARMUP` | `1` | Warm index + model on startup. |
| `KNOWLEDGE_DIR`, `CACHE_DIR`, `INDEX_DIR`, `EMBED_CACHE_DIR` | paths under `server/` | Override storage locations. |
